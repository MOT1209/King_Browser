# MCP development

How King Browser's MCP server is built and how to extend it. The security controls are in the `mcp-security` skill; the tool checklist is in `mcp-tool-development`. This page is the narrative version.

## Layout

| File | Role |
| :--- | :--- |
| `electron/mcpServer.ts` | Express app on `127.0.0.1:3020`: routes, auth, rate limit, `TOOLS`, `TOOL_PERMISSIONS`, `TOOL_ALIASES`, dispatch to the renderer |
| `electron/main/mcpProtocol.ts` | JSON-RPC handling shared by both transports (`initialize`, `tools/list`, `tools/call`) |
| `electron/main/mcpStreamableHttp.ts` | `/mcp` session and Origin logic |
| `electron/main/mcpContent.ts` | Result to MCP content blocks (image blocks for screenshots), error formatting |
| `electron/main/mcpClientConfig.ts` | Generated client configuration for Settings -> MCP |
| `mcp-bridge.ts` -> `mcp-bridge.mjs` | stdio bridge; the `.mjs` is generated by `npm run build:bridge` and CI fails if it drifts |
| `src/hooks/useBrowserAgentBridge.ts` | Renderer-side implementation of page and tab tools |

Request path: client -> auth (bearer token), Host and Origin checks, rate limit -> `tools/list` filtered by enabled tier or `tools/call` -> permission check -> alias resolution -> policy engine (approval if sensitive) -> renderer handler -> result or `Error:` string.

## Tool tiers

| Tier | Meaning | Default |
| :--- | :--- | :--- |
| `safe` | Metadata, run control, scrolling, waiting | Enabled |
| `medium` | Reads page content, navigates, manages tabs | Hidden until enabled in Settings -> MCP |
| `sensitive` | Types, presses keys, selects, logs in, fills forms | Hidden until enabled; every call also passes the approval policy |

Tier and approval are separate: enabling a tool in Settings makes it callable; the policy engine still decides per call whether a human must approve it. There is no mode that disables approval.

## Add a tool

1. Choose the tier (when unsure: `sensitive`).
2. Add the `TOOLS` entry. Required quality bar, enforced by `tests/mcp_tool_schemas.test.ts`: name `browser_<snake_case>`, description of 20+ characters, `inputSchema.type = "object"`, every property typed (`string|number|integer|boolean|array|object`) and described, arrays declare `items`, `required` names only declared properties.
3. Add `TOOL_PERMISSIONS[name]`.
4. Implement the handler and validate the arguments again there.
5. Add the policy rule and redaction in `policyEngine.ts`.
6. Add the tool to `MCP_TOOLS` in `src/components/settings/McpSection.tsx`.
7. Add tests: policy case, handler case, failure case. Register new files in `tests/runAll.ts`.
8. Update the two counts in `README.md` and the tool families in `AGENTS.md`.

Failure responses are strings beginning `Error:` (see `formatToolError`); they never include stack traces, tokens or typed text.

## Test

```bash
npm test                                  # all Node suites, including the MCP ones
npm run build:bridge && git diff --exit-code mcp-bridge.mjs
npm run test:integration                  # needs the app running; drives it end to end
```

## Diagnose

| Symptom | Check |
| :--- | :--- |
| 401 | Token wrong or sent in the query string (only `Authorization: Bearer` is accepted) |
| 403 | Non-local Host header (any route) or foreign Origin (`/mcp`) |
| 404 on `/mcp` | Unknown or expired `Mcp-Session-Id`; initialize again |
| `Cannot POST /sse` | An OpenCode `remote` entry points at `/sse`; use `/mcp` |
| Tool missing from `tools/list` | Its tier is not enabled in Settings -> MCP |
| "approval required" | Working as designed; wait for the human, do not retry |
| Client times out on a sensitive tool | Client timeout is below the 180 s the bridge allows (120 s approval + 15 s execution) |
